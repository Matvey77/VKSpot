# Безопасность

VKSpot хранит коллекции, историю и настройки локально в SQLite. Телеметрии и скрытой передачи пользовательских данных нет. Приложение не запрашивает и не сохраняет пароли VK или Spotify.

- Веб-страницы сервисов изолированы от Node.js (`contextIsolation`, sandbox); renderer обращается к main только через типизированный `contextBridge`. IPC проверяет отправителя и валидирует данные.
- Скрипты интеграций читают отображённый DOM в изолированном мире; секреты и закрытые API VK не извлекаются. Разрешения и загрузки в окне VK заблокированы; профили VK и Spotify разделены. VK по умолчанию работает напрямую; его прокси настраивается отдельно от Spotify.
- Spotify API использует OAuth 2.0 PKCE и callback только на `127.0.0.1:43823`. Токены хранятся через Electron `safeStorage`; если системное защищённое хранилище недоступно, токен на диск не записывается. В Linux резервный backend `basic_text` не считается защищённым: нужен доступный системный менеджер секретов, а также работающая песочница Chromium (см. [docs/maintenance.md](docs/maintenance.md)).
- SQLite-триггер защищает исходные поля коллекции. Данные приложения находятся в системной папке пользователя; сессию VK можно очистить из интерфейса.
- Локальные аудиофайлы не загружаются в Spotify: их индексирует настольный клиент Spotify на твоём устройстве.

Для приватного сообщения об уязвимости открой **Security → Advisories → Report a vulnerability** на GitHub. Этот канал доступен после включения Private vulnerability reporting владельцем репозитория. Если кнопки нет, создай issue только с просьбой указать приватный канал, без описания уязвимости и данных.

Укажи версию, шаги воспроизведения и обезличенный пример. Не публикуй секреты, личные архивы, токены или cookies в issue и тестовых фикстурах.
