# Участие в VKSpot

- Используйте Node.js 24 LTS и `npm ci` с зафиксированным package-lock.json.
- Перед изменением прочитайте docs/project-brief.md и docs/product.md.
- UI следует DESIGN.md; основной дизайн-навык проекта — Impeccable.
- Размещайте файлы по [структуре репозитория](docs/repository-structure.md).
- Исходные записи, позиции и повторы не должны изменяться при рабочих правках.
- Любые изменения описания отменяемы; «исключить» не означает удалить.
- Правила неясных записей не менять без обсуждения с владельцем проекта.
- Не добавляйте обязательные платные API, облачный сервер и скрытую телеметрию.
- Не храните пароли, cookies, токены и пользовательские архивы в репозитории.
- Адаптер должен явно сообщать, какие возможности проверены, а какие нет.
- Проверяйте порядок и повторные вхождения после ошибок и перезапуска.
- Добавляйте тест, который проверяет реальный риск изменения, а не копирует код.
- Перед PR выполните `npm run build`, `npm test`, `npm run test:e2e`.
- Публикация выпусков и изменение пользовательского Spotify не выполняются автоматически тестами.

Для воспроизведения проблем используйте синтетические записи и временную
изолированную папку данных (`VKSPOT_DATA_DIR`). Перед очисткой временной папки
проверяйте её абсолютный путь и принадлежность тестовому каталогу.

Для проверки готового Windows-выпуска задайте `VKSPOT_TEST_EXECUTABLE` полным
путём к `release/<версия>/win-unpacked/VKSpot.exe` и запустите
`npx playwright test tests/e2e/review.spec.ts tests/e2e/welcome.spec.ts`.
Эти сценарии создают временные профили, подменяют Spotify синтетическими
ответами и не используют рабочую коллекцию. После проверки уберите переменную.
