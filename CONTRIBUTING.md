# Руководство для участников разработки (CONTRIBUTING)

Благодарим за интерес к развитию проекта VKSpot! Перед внесением изменений, пожалуйста, ознакомьтесь с архитектурными принципами и правилами разработки.

---

## 1. Подготовка окружения

- **Среда выполнения:** Node.js 24 LTS (строго рекомендуется для полного соответствия рантайму `node:sqlite`).
- **Установка зависимостей:** используйте исключительно `npm ci` для детерминированной установки из зафиксированного `package-lock.json`.
- **Перед началом работы:** обязательно ознакомьтесь с [docs/product.md](docs/product.md), [docs/project-brief.md](docs/project-brief.md) и [DESIGN.md](DESIGN.md).

---

## 2. Архитектурные правила и стандарты

1. **Неизменяемость оригинала:** Исходные записи (`source`), позиции (`position`) и намеренные повторы треков ни при каких условиях не должны модифицироваться или склеиваться.
2. **Обратимость действий:** Любые пользовательские правки метаданных в рабочей копии должны поддерживать операцию отмены (`Undo`).
3. **Исключение не означает удаление:** Пометка «исключить» сохраняет трек в базе данных и архивах, но исключает его из итогового плана переноса в плейлист.
4. **Принцип приватности и бесплатности:**
   - Запрещено добавлять зависимости от обязательных платных API, облачных серверов или телеметрии.
   - Запрещено сохранять пароли, токены, cookies и реальные архивы медиатек в кодовой базе или тестах.
5. **Дизайн-система:** Интерфейс разрабатывается в соответствии со спецификацией [DESIGN.md](DESIGN.md) (принципы Impeccable: архивный строгий стиль, отсутствие декоративных замедляющих анимаций, доступность WAI-ARIA).
6. **Размещение файлов:** Строго следуйте [docs/repository-structure.md](docs/repository-structure.md). Бизнес-логику выносите в `src/core/`, не привязывая ее к Electron API. Сервисы главного процесса разделяйте на специализированные модули в `src/main/` (`network.ts`, `files.ts`, `vk-session.ts`), а представления вкладок и модальные диалоги — в `src/renderer/src/`.

---

## 3. Тестирование и верификация

Каждое изменение кодовой базы должно сопровождаться модульными или сквозными тестами:

- **Синтетические данные:** Для тестов используйте только синтетические фикстуры и изолированные временные папки профилей данных (`VKSPOT_DATA_DIR`).
- **Модульные тесты:** Запуск через Vitest:
  ```sh
  npm test
  ```
- **Сквозные E2E-тесты:** Запуск Playwright с реальным экземпляром Electron в фоновом режиме:
  ```sh
  npm run test:e2e
  ```
- **Тестирование готового собранного дистрибутива:**
  Укажите переменную окружения `VKSPOT_TEST_EXECUTABLE` с полным путем к исполняемому файлу:
  ```sh
  $env:VKSPOT_TEST_EXECUTABLE = "D:\Projects\VKSpot\release\0.1.36\win-unpacked\VKSpot.exe"
  npx playwright test tests/e2e/review.spec.ts tests/e2e/welcome.spec.ts
  ```

## 4. Чек-лист перед отправкой Pull Request

Перед созданием коммита и отправкой изменений убедитесь, что все автоматические проверки проходят успешно:

```sh
# 1. Проверка строгой типизации TypeScript
npm run typecheck

# 2. Проверка линтера
npm run lint

# 3. Проверка форматирования кода
npm run format:check

# 4. Прогон всех модульных тестов
npm test

# 5. Прогон всех сквозных тестов
npm run test:e2e

# 6. Пробная сборка приложения
npm run build
```
