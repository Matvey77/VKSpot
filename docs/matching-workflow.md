# Фоновый поиск и алгоритм сопоставления коллекции

Документ описывает логику работы поискового механизма, систему классификации треков и рабочий процесс разбора медиатеки в приложении VKSpot.

---

## 1. Общий порядок работы

Поиск кандидатов в Spotify по умолчанию выполняется во встроенном изолированном веб-представлении Chromium без необходимости создавать приложение Spotify Developer или указывать Client ID. Поиск через официальный Web API остается доступным в качестве альтернативы в «Параметрах поиска».

1. **Импорт и автозапуск поиска:**
   - После импорта списка VK поиск запускается автоматически (если не снят соответствующий флаг в окне подтверждения).
   - Задание выполняется в фоновом режиме, не блокируя навигацию по приложению и разбор уже найденных результатов.
2. **Пакетное выделение однозначных совпадений:**
   - Кнопка **«Выделить совпадения»** находит все записи со статусом «Совпадают данные» в текущей выборке фильтров и активирует соответствующий фильтр.
   - Действие **«Подтвердить выбранные»** применяется исключительно к однозначным совпадениям. Любое изменение метаданных в процессе сопоставления безопасно отменяется кнопкой «Отменить последнюю правку» (`Undo`).
3. **Пошаговый разбор спорных вариантов:**
   - Инспектор таблицы отображает карточку оригинала VK рядом со списком кандидатов Spotify. Откройте его нажатием на строку или стрелку разбора.
   - Пользователь может выбрать подходящую версию, пометить выделенные записи через меню «Другие действия» как «Нужен локальный файл», отложить разбор или исключить их из переноса.
   - После выбора варианта решение сохраняется в строке. Для следующей записи используйте таблицу и фильтры.
4. **Обработка отсутствующих треков:**
   - Статус «Без результатов» присваивается записям, по которым Spotify вернул явное сообщение об отсутствии результатов.
   - Пользователь может скорректировать поисковый запрос в рабочей копии либо перевести трек в категорию «Нужен локальный файл».
5. **Привязка локальных файлов:**
   - Для треков, отсутствующих в каталоге стриминга, пользователь привязывает имеющийся аудиофайл с диска через инспектор или экран разбора.

## 2. Группы разбора (`ReviewGroup`)

Каждая строка коллекции относится к одной из семи взаимоисключающих групп, определяющих ее текущий статус:

| Идентификатор   | Отображаемое название | Критерии включения                                                                       | Следующее действие                                               |
| :-------------- | :-------------------- | :--------------------------------------------------------------------------------------- | :--------------------------------------------------------------- |
| `pending`       | **Не искали**         | Поисковый запрос еще не отправлялся в Spotify.                                           | Дождаться очереди фонового поиска или запустить вручную.         |
| `exact`         | **Совпадают данные**  | Найден кандидат, на 100% удовлетворяющий строгим критериям совпадения метаданных.        | Пакетное подтверждение кнопкой «Подтвердить выбранные».          |
| `review`        | **Проверить версию**  | Кандидаты найдены, но есть различия в версиях, тайминге или составе артистов.            | Ручной выбор в «Разборе коллекции» с предпрослушиванием.         |
| `missing`       | **Без результатов**   | Поиск завершен с явным сообщением об отсутствии треков в каталоге Spotify.               | Коррекция запроса в рабочей копии или статус «Нужен файл».       |
| `local-pending` | **Нужен файл**        | Пользователь определил, что трек должен быть перенесен из локального аудиофайла.         | Привязка физического аудиофайла (`.mp3`, `.flac` и др.) с диска. |
| `deferred`      | **На потом**          | Пользователь временно отложил решение по данной композиции.                              | Возврат к разбору после завершения основной части библиотеки.    |
| `ready`         | **Решено**            | Запись полностью подготовлена: подтвержден Spotify URI, привязан файл или трек исключен. | Запись готова к включению в итоговый план переноса.              |

## 3. Критерии совпадения данных (`metadataMatch`)

Исполняемая спецификация алгоритма зафиксирована в модуле `src/core/matching.ts`. Для автоматического перехода трека в группу «Совпадают данные» должны одновременно выполняться следующие правила:

1. **Нормализация Unicode и снятие диакритики:**
   - Приведение строк к нормальной форме NFD со снятием диакритических знаков диапазона `\u0300-\u036f` и последующей нормализацией NFKC.
   - Имена вида `Beyoncé` и `Beyonce`, `JAŸ-Z` и `JAY-Z` признаются строго идентичными.
2. **Фолдинг омоглифов кириллицы и латиницы:**
   - Автоматическая замена визуально неразличимых букв (`а`->`a`, `в`->`b`, `е`->`e`, `к`->`k`, `м`->`m`, `н`->`h`, `о`->`o`, `р`->`p`, `с`->`c`, `т`->`t`, `х`->`x`, `у`->`y`, `і`->`i`, `ј`->`j`).
   - Псевдонимы `MOT` (латиница) и `МОТ` (кириллица), `CMH` и `СМН` распознаются как одинаковые.
3. **Дедупликация приглашенных артистов:**
   - Алгоритм извлекает гостевых исполнителей из названий треков вида `(feat. ...)`, `[feat. ...]`, `with ...` и объединяет их с основным полем артистов.
   - Треки вида `JEEMBO, ICEGERGERT — ПОКАЖИ КОЗУ (feat. ICEGERGERT)` безошибочно сопоставляются со студийной карточкой Spotify `ПОКАЖИ КОЗУ` без ложных расхождений по составу авторов.
4. **Автосопоставление идентичных версий:**
   - Если исходная запись VK и кандидат в Spotify содержат одинаковый маркер версии (`Remix`, `Mix`, `Edit`, `2026 Version`, `Speed Up`, пользовательский тег), такое совпадение не блокируется правилом версионности и автоматически признается допустимым при совпадении длительности.
   - Различные версии (например, оригинал против `Remix` или `Acoustic`) безусловно направляются на ручную проверку.
5. **Мягкая пунктуация для ремиксов:**
   - Дефисы и скобки вокруг маркеров версий сопоставляются толерантно (`FALLEN (BALDSCUM remix)` <-> `FALLEN BALDSCUM remix`).
   - Если имя ремиксера указано в составе исполнителей кандидата Spotify, совпадение признается успешным.
6. **Настраиваемый допуск по хронометражу:**
   - По умолчанию включен безопасный допуск до 5 секунд (`MATCH_DURATION_TOLERANCE_SECONDS = 5`). Это компенсирует паузы тишины в начале и конце MP3-файлов VK относительно мастер-записей Spotify.
   - При отключении настройки «Расширенный допуск по времени» применяется строгий лимит в 2 секунды.
7. **Интеллектуальное разрешение дубликатов релизов (сингл vs альбом):**
   - Если Spotify возвращает несколько кандидатов с совпадающим названием и артистом, алгоритм выбирает основной студийный релиз по внутренней популярности Spotify и точности хронометража, автоматически отсекая концертные (live) записи.
8. **Треки с отсутствующей длительностью в VK:**
   - Если у исходного трека в VK отсутствовала длительность (`source.duration === null`), совпадение подтверждается автоматически только при 100% совпадении названия и артиста, отсутствии признаков специальных версий и согласованности длительностей всех предложенных кандидатов (разброс не более 5 секунд). При наличии разных версий трек остается на ручной разбор.

## 4. Фоновые очереди и устойчивость к сбоям

- **Сохранность курсора:** Фоновый процесс сохраняет индекс текущей строки в SQLite. При перезапуске приложения или сбое питания очередь продолжается с сохраненной позиции.
- **Приоритет ручной паузы:** Если пользователь нажал кнопку «Пауза», процесс завершает текущий сетевой запрос и гарантированно не возобновляется автоматически до явного действия пользователя.
- **Обработка платформенных лимитов Spotify (HTTP 429):**
  - При получении ответа 429 с кодом `QUOTA_EXCEEDED` интерфейс сообщает об исчерпании суточной квоты.
  - При штатном ограничении частоты запросов считывается заголовок `Retry-After`. Приложение переходит в состояние ожидания с локальным таймером обратного отсчета.
  - При включенном «Автопродолжении» (включено по умолчанию) главный процесс автоматически возобновляет поиск по истечении таймера без дополнительных сетевых проверок.
- **Переключение провайдера на лету:**
  - Задачу поиска, приостановленную из-за лимитов Web API, можно в один клик переключить на браузерный поиск («Продолжить через страницу Spotify») без сброса курсора и потери ранее найденных кандидатов.

## 5. Доступность интерфейса и навигация

- Группы результатов и статусы выбираются доступными с клавиатуры выпадающими списками. Таблица поддерживает фокус строк и открытие инспектора с клавиатуры.
- Все недоступные действия сопровождаются всплывающими подсказками (`ExplainedButton.tsx`), объясняющими точную причину блокировки (ожидание кулдауна, отсутствие подключения или выполнение другой задачи). Подсказки закрываются клавишей `Escape` и доступны для экранных дикторов.
