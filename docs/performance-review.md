# Ревью производительности и рефакторинг 0.1.31

Дата: 21 октября 2026 года. База сравнения: готовая Windows-сборка 0.1.30. Изменения выполнены в ветке `codex/performance-refactor`.

## Подтверждённые причины задержек

1. Любое уведомление о прогрессе или точечной правке запускало полный `state()`. Для 9000 строк с двумя кандидатами и исходными текстами это около 9,48 МБ. Передача между процессами, копирование и повторный анализ происходили даже при изменении одной заметки.
2. Полные снимки создавали новые ссылки на все строки и правила сопоставления. Поэтому кэши React теряли смысл, а статусы и сводки рассчитывались заново.
3. Виртуальная прокрутка ограничивала DOM, но TanStack Table всё равно строил полную модель коллекции. Таблица заменена на непосредственный рендер видимого диапазона через TanStack Virtual.
4. Хранилище строило индекс всех строк для каждой правки. Поиск одной строки был линейным; получение одного задания читало и разбирало весь список заданий.
5. С каждым продвижением курсора заново сохранялись большие списки `rowIds` и планы переноса. Теперь они вынесены в `job_details` и записываются при изменении входных данных задания.
6. Движение разделителя меняло React-состояние всего рабочего пространства на каждом событии мыши. Теперь движения объединяются по кадрам, а сохранение ширины выполняется при отпускании.
7. Руководство и схемы валидации попадали в начальный граф загрузки. Константы отделены от схем, руководство загружается отдельно; включена минификация production-бандла.

## Одинаковый синтетический сценарий

Замер запускает настоящий Electron в отдельном временном профиле на том же Windows-компьютере. Он импортирует 9000 записей, добавляет два кандидата на строку, выполняет 12 правок с паузой 180 мс, вводит `Song 8999` и открывает инспектор. Исходные тексты и кандидаты синтетические; аккаунты и сеть VK/Spotify не используются.

| Передаваемый обычный снимок состояния | 9 480 693 байта | 732 байта при отсутствии изменений коллекции |
| Медиана штатного обновления           |        151,5 мс |                                       0,3 мс |

Время ввода включает искусственную задержку 30 мс между символами. Числа показывают этот конкретный сценарий и компьютер; это не обещание одинаковой задержки на любом оборудовании. Сетевые ограничения и скорость сайтов измерением не покрываются.

Полный снимок по-прежнему нужен при первой загрузке и восстановлении просроченного курсора. Он не стал меньше и занимает около 160 мс в контрольном вызове 0.1.31. Устранена его повторная передача при каждой операции. Изменение строки передаёт только эту строку; переименование передаёт метаданные без треков.

## Структура и надёжность

- У репозиториев коллекций, очереди и настроек отдельная ответственность; SQL-запросы подготавливаются один раз.
- Добавлен ограниченный журнал изменений, отдельный контракт синхронизации и локальная копия состояния с сохранением ссылок.
- Корневой компонент разделён на оболочку, контроллер, навигацию и диалоги. Функции интерфейса собраны в `features/`; таблица и инспектор разделены.
- CSS разделён по областям с сохранением каскада. Удалены стили отсутствующего экрана разбора и неиспользуемый компонент вкладок.
- Исправлено сопоставление повторных вхождений при синхронизации: один старый трек используется один раз, UUID и независимые решения сохраняются.
- Отмена новой синхронизации восстанавливает оригинал и рабочую копию из транзакционного снимка. Старые записи истории без снимка отклоняются с объяснением.
- Короткая частичная выгрузка не удаляет непрочитанный хвост. Если сохранённые прежние решения увеличивают число записей, полнота явно остаётся неподтверждённой.
- Удаление и синхронизация коллекции требуют остановки её активного задания, чтобы запрос в полёте не записал результат в заменённые строки.

## Как повторить

```powershell
npm run build
npm run perf

# Сравнить с конкретной готовой сборкой:
$env:VKSPOT_TEST_EXECUTABLE = 'D:\Projects\VKSpot\release\0.1.30\win-unpacked\VKSpot.exe'
$env:BENCHMARK_OUTPUT = 'D:\Projects\VKSpot\.local\performance\baseline.json'
npm run perf
```

Без `VKSPOT_TEST_EXECUTABLE` используется текущий `out/`. Результат по умолчанию сохраняется в `.local/performance/latest.json`. Профиль создаётся отдельно и удаляется после закрытия тестового приложения. Персональная медиатека не изменяется.

Постоянные проверки защищают содержимое коллекции, откаты, независимые повторы, миграцию старой очереди, восстановление курсора и размер дельт. E2E дополнительно запрещает обращения интерфейса к полному `state()` после открытия коллекции и проверяет фильтрацию и изменение ширины на 9000 строках. Временные пороги в CI не фиксируются, чтобы не зависеть от скорости тестового компьютера.

Итоговая проверка выпуска: 75 модульных тестов и 42 E2E-сценария прошли успешно. Все E2E выполнены на готовом Windows exe 0.1.31. TypeScript, ESLint, Prettier и сборка также завершились без ошибок. Светлая и тёмная темы проверены при ширине окна 940 и 1440 px.
