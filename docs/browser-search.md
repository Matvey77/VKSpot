# Поиск через страницу Spotify

В 0.1.11 это основной способ поиска. Он открывает обычную страницу поиска Spotify
в изолированном Chromium-представлении внутри VKSpot, меняет запросы и читает
отрисованные строки: Spotify URI, название, исполнителей, альбом и длительность.
Никаких дополнительных программ, Client ID или аккаунта VKSpot для этого не нужно.

После импорта поиск запускается автоматически, если оставлена галочка в просмотре
списка. Восстановление готового архива не запускает новый поиск автоматически.
В таблице можно приостановить очередь и продолжить её. Параметры доступны через
«Параметры поиска», способ нового поиска также задаётся в настройках.

Для старого API-задания нажми «Продолжить через страницу Spotify» в коллекции или
заданиях. Продолжение использует тот же курсор и исходные вхождения. Уже найденные
варианты остаются на месте. Срок ожидания API сохраняется отдельно и продолжает
ограничивать API-перенос; переключение не сбрасывает серверную квоту.

Если Spotify требует вход или проверку, очередь останавливается на текущей записи.
Подсказка открывает страницу в том же окне. Заверши проверку и нажми «Продолжить
поиск». VKSpot не читает пароль, cookies, токены страницы или внутренние API Spotify.
Скрытый служебный блок reCAPTCHA сам по себе не считается запросом помощи.

Результаты разных способов кешируются отдельно; повторный запрос внутри одного
способа переиспользуется без удаления повторов в коллекции. Ошибка сети,
неподдерживаемая разметка или отсутствующая длительность не помечают трек как
ненайденный. Пустой результат принимается только по явному сообщению Spotify.
Кандидат без читаемого исполнителя остаётся видимым с соответствующей подписью;
такой запрос требует ручного разбора. Spotify может вернуть неточные варианты
даже для бессмысленного запроса — совпадением они автоматически не становятся.

Ручная пауза сохраняется после перезапуска. При HTTP 429 с доступным Retry-After
ожидание страницы учитывается отдельно от API, затем фоновая очередь может
продолжиться автоматически. Проверки входа и непонятные ошибки без срока
ожидания требуют действия пользователя, автоматического бесконечного повтора нет.

18.10.2026 в отдельном профиле выполнены три живых запроса без API-входа:
Temper City / Self Aware, Daft Punk / Get Lucky и заведомо искусственный запрос.
Первые два вернули кандидатов с метаданными; искусственный тоже вернул неточные
варианты и требует ручного разбора. Использовался локальный прокси VPN.
Плейлисты и коллекция владельца не менялись. Evidence:
`.local/evidence/browser-search-live-0111.json`.

Это подтверждает работоспособность адаптера на проверенных страницах. Долгая
очередь из 8000+ записей, вход на реальном аккаунте во встроенной странице и
отсутствие собственных ограничений сайта пока не подтверждены. Создание плейлиста
по-прежнему использует официальный API; этот модуль автоматизирует поиск кандидатов.
