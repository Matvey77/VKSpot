# Поиск через веб-интерфейс Spotify

Браузерный поиск — основной механизм поиска кандидатов в приложении VKSpot. Он автоматизирует взаимодействие с веб-плеером `open.spotify.com` во встроенном изолированном представлении Chromium без необходимости создавать приложение Spotify Developer и получать Client ID.

---

## 1. Назначение и преимущества

- **Нулевой порог входа:** Пользователю не требуется создавать приложение на портале Spotify for Developers, разбираться с Redirect URI и настраивать авторизацию PKCE.
- **Работа без подписки Spotify Premium:** Поиск кандидатов в веб-плеере открыт для публичного каталога и не требует учетной записи разработчика.
- **Полная локальность и приватность:** Приложение не перехватывает пароли, токены и cookies страницы Spotify. Все операции чтения производятся исключительно над отрисованным DOM-деревом в изолированном контексте.
- **Обход лимитов Developer Quota:** Веб-плеер Spotify использует собственные механизмы отдачи поисковой выдачи, не зависящие от жестких квот Web API в режиме разработки (Development Mode).

---

## 2. Архитектура и механизм работы (`src/main/integrations/spotify/browser.ts`)

### Изолированное окружение

Поиск выполняется внутри компонента `WebContentsView` в выделенном изолированном профиле сессии `persist:vkspot-spotify-browser`:

- **Подавление фонового троттлинга:** Опция `backgroundThrottling: false` обеспечивает стабильную фоновую работу очереди даже при свернутом окне VKSpot.
- **User-Agent:** Используется стандартная строка идентификатора десктопного Chromium (без вкраплений имени `Electron` или `VKSpot`), что исключает перенаправление на мобильную версию Spotify.
- **Защита от утечек и навигации:** Обработчики `will-navigate` и `will-redirect` блокируют переход на любые домены за пределами `spotify.com`, `scdn.co`, `spotifycdn.com`, `google.com` (reCAPTCHA) и `about:blank`.
- **Беззвучный режим:** Аудиопоток веб-плеера заглушен (`setAudioMuted(true)`), предотвращая случайное воспроизведение треков при загрузке страниц.
- **Сетевой прокси (`src/main/platform/network.ts`):** Сессия браузера независимо маршрутизируется через пользовательский HTTP/SOCKS5 прокси без влияния на соединение с серверами VK.

### Санитизация поисковых запросов

Перед отправкой в адресную строку URL (`https://open.spotify.com/search/<query>/tracks`) поисковая строка проходит специальную очистку:

- Удаляются символы обратного слэша `\`, которые Chromium нормализует в прямые слэши `/`, приводя к искажению структуры пути URL.
- Удаляются неразрывные пробелы, символы табуляции и переводы строк.
- Строка кодируется через `encodeURIComponent` и сопоставляется с фактическим `location.pathname` браузера для подтверждения завершения загрузки именно запрошенной страницы.

### Чтение и парсинг DOM-разметки

Функция `readSpotifySearch(query)` выполняется в изолированном мире (`isolatedWorld`) и считывает элементы `[data-testid="tracklist-row"]`:

- **Spotify URI:** Извлекается из атрибута `href` ссылки на трек (`/track/([A-Za-z0-9]{22})`).
- **Название трека:** Считывается текстовое содержимое заголовка.
- **Список артистов:** Считываются все ссылки `a[href*="/artist/"]` с дедупликацией.
- **Альбом:** Извлекается текстовое значение ссылки `a[href*="/album/"]`.
- **Длительность:** Поддерживается парсинг как стандартных минутных форматов (`mm:ss`), так и часовых таймингов (`h:mm:ss`, например `1:12:28` для диджей-сетов и подкастов).

### Мультиязычное распознавание пустой выдачи

Поиск признается завершенным без результатов (`kind: 'empty'`) только при обнаружении явного системного сообщения Spotify на странице. Поддерживаются регулярные выражения для основных языковых локалей:

- Русский: `треки не найдены`, `ничего не найдено`, `не удалось найти`, `нет ли опечаток`, `перефразируйте`.
- Английский: `no tracks found`, `no results for`, `couldn't find`, `spelled correctly`.
- Немецкий: `keine ergebnisse`, `richtig geschrieben`.
- Испанский: `no se encontraron`.
- Французский: `aucun résultat`.

## 3. Обработка интерактивных проверок (Human-in-the-Loop)

Если Spotify запрашивает подтверждение личности (Cloudflare challenge, reCAPTCHA) или требует вход в аккаунт:

1. Поисковый процесс фиксирует наличие блокирующего фрейма или текст «Подтвердите, что вы человек».
2. Задача поиска автоматически приостанавливается на текущем курсоре с установкой статуса `attention`.
3. В интерфейсе VKSpot появляется информационная плашка с предложением открыть окно Spotify.
4. По клику поверх интерфейса монтируется панель `SpotifyPanel`, открывающая встроенный браузер для пользователя.
5. Пользователь проходит капчу или авторизуется непосредственно на защищенном сайте Spotify (пароли не перехватываются и не сохраняются VKSpot).
6. После решения проверки пользователь нажимает «Продолжить поиск», и очередь возобновляет работу со строки, на которой остановилась.

## 4. Обработка сетевых лимитов и кэширование

- **Кэширование результатов:** Ответы сохраняются в локальной таблице `cache` SQLite с префиксом `spotify-browser-v1:<query>`. Повторные поиски аналогичных треков берутся из кэша мгновенно без обращения к сети.
- **Реакция на HTTP 429:** Сетевой перехватчик `onHeadersReceived` отслеживает статус 429 от `open.spotify.com`. При получении ответа извлекается заголовок `Retry-After` (по умолчанию 60 секунд при его отсутствии).
- **Автопродолжение:** В базу данных записывается точная временная метка `retryAt`. Локальный таймер главного процесса возобновляет поиск сразу по истечении кулдауна.
