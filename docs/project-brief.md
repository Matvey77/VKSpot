# Архитектурный бриф и реестр решений (ADR)

Документ фиксирует системные требования, ключевые бизнес-правила и обоснование архитектурных решений приложения VKSpot (актуализировано для версии 0.1.29).

---

## 1. Контекст и цели проекта

- **Наименование проекта:** VKSpot.
- **Миссия:** Автономный перенос личной музыкальной библиотеки из VK Музыки в Spotify с сохранением точного порядка треков, авторских версий и пользовательских дубликатов.
- **Слоган:** «Каждый трек. Каждая версия. Твой порядок».
- **Исходная ситуация:**
  - Личная коллекция пользователя насчитывает 8 000+ треков.
  - Значительная часть треков — уникальные аудиозаписи, загруженные пользователем в VK самостоятельно (ремиксы, лайв-версии, мэшапы, редкие треки), отсутствующие в каталоге стриминговых сервисов.
  - Наличие заблокированных правообладателями записей, чьи метаданные сохранены в VK.
  - Потребность в смешанном переносе: перенос каталожных совпадений напрямую в плейлист Spotify плюс подготовка и структурирование локальных MP3-файлов для отсутствующих записей с сохранением единой сквозной нумерации.
- **Принцип качества:** Надежность, прозрачность для пользователя и сохранность порядка важнее скорости разработки и минимализма дистрибутива.

---

## 2. Фундаментальные продуктовые требования

1. **100% бесплатность и автономность:**
   - Основные функции работают без покупок, скрытых подписок и внешних облачных серверов.
   - Обработка и хранение выполняются исключительно на локальном компьютере пользователя.
   - Исключена зависимость от платных сторонних AI-сервисов или подписок переноса.
2. **Неизменяемость оригинала:**
   - Извлеченный сырой список VK неприкосновенен и защищен на уровне СУБД SQLite триггером `source_immutable`.
   - Любые правки названий, исполнителей и привязок производятся в рабочей копии (`working`), полностью обратимы и протоколируются в таблице истории изменений.
3. **Сохранение идентичности каждого вхождения:**
   - Каждое вхождение трека имеет собственный UUID и позиционный индекс.
   - Одинаковые треки, повторно добавленные пользователем в плейлист VK, не схлопываются и не удаляются.
4. **Прозрачность версий:**
   - Ремиксы, каверы, sped-up, slowed и концертные версии не заменяются молча стандартными студийными треками Spotify. Сомнительные совпадения требуют явного решения пользователя.
5. **Честность лимитов платформ:**
   - При превышении частоты запросов или исчерпании квоты Spotify (HTTP 429) приложение отображает точное время ожидания из заголовка `Retry-After` и локальный таймер обратного отсчета без попыток слепого обхода.

## 3. Реестр архитектурных решений (ADR)

### ADR-1: Платформа и среда выполнения — Electron 44 + Node.js 24 LTS + React 19

- **Контекст:** Требовалось десктопное приложение для Windows x64 с возможностью сложного парсинга динамических веб-страниц VK и Spotify.
- **Рассмотренные альтернативы:** Tauri (Rust + WebView2), чистый Node.js CLI, Python/Qt.
- **Решение:** Electron 44 на базе Node.js 24 LTS и Chromium.
- **Обоснование:**
  - Tauri использует системный WebView2, поведение которого зависит от обновлений Windows и ограничено в тонком управлении сессиями Chromium (`WebContentsView`, изоляция cookies, управление аудио-пайплайном).
  - Полноценный встроенный движок Chromium в Electron обеспечивает независимые изолированные профили (`persist:vkspot-vk`, `persist:vkspot-spotify-browser`), поддержку выполнения изолированных скриптов (`isolatedWorld`) и стабильную работу с медиапотоками без сторонних системных зависимостей.

### ADR-2: Локальная СУБД — Встроенный модуль `node:sqlite` с WAL-журналированием

- **Контекст:** Необходима быстрая, надежная транзакционная база данных для хранения коллекций (10 000+ записей), истории правок, кэша запросов и очереди задач.
- **Рассмотренные альтернативы:** `better-sqlite3`, Drizzle ORM, NeDB, JSON-файлы.
- **Решение:** Нативный встроенный модуль `node:sqlite` (доступен в Node.js 24 / Electron 44) в режиме WAL (`Write-Ahead Logging`).
- **Обоснование:**
  - `better-sqlite3` требует перекомпиляции нативных бинарных модулей под ABI конкретной версии Electron при сборке (`electron-rebuild`), что часто приводит к сбоям сборки на Windows.
  - Нативный `node:sqlite` встроен в рантайм, не требует внешних `.node` файлов, обладает высокой скоростью и нативной поддержкой синхронных транзакций.
  - Отказ от тяжелых ORM в пользу прозрачных параметризованных SQL-запросов и Zod-валидации на границах модуля.
  - В v0.1.29 добавлено in-memory кэширование коллекций в `Store`, сократившее повторные выборки при опросе состояния до 0.001 мс.

### ADR-3: Двухконтурный поиск в Spotify — Страничный поиск по умолчанию и официальный API для экспорта

- **Контекст:** Для переноса музыки в Spotify классический путь через Web API требует регистрации приложения в Spotify Developer Dashboard, создания Client ID и настройки Redirect URI. Более того, Spotify ввел режим Development Mode с жестким лимитом в 5 пользователей и требованием наличия подписки Spotify Premium у владельца приложения.
- **Решение:**
  - **Контур поиска (по умолчанию):** Автоматизированный поиск через встроенную веб-страницу `open.spotify.com` во внутреннем изолированном окне Chromium без запроса Client ID у пользователя.
  - **Контур переноса (опционально):** Официальный Spotify Web API с авторизацией OAuth 2.0 PKCE, используемый только на финальном этапе создания плейлиста.
- **Обоснование:** Устраняется барьер входа. 95% работы с приложением (сбор, сопоставление, разбор версий, подготовка локальных файлов, формирование плана) пользователь выполняет сразу после установки без авторизации в Developer Dashboard.

### ADR-4: Сетевая изоляция и независимые сетевые прокси

- **Контекст:** Сервисы Spotify заблокированы или ограничены в ряде регионов (возвращают HTTP 403 Forbidden), тогда как медиапотоки VK Музыки транслируются через российские CDN и блокируются при обращении через зарубежные VPN/прокси.
- **Решение:**
  - Раздельные сетевые сессии Electron: сессия Spotify (`persist:vkspot-spotify-browser` и системный клиент) направляется через настроенный пользователем локальный HTTP/SOCKS5 прокси.
  - Сессия VK (`persist:vkspot-vk`) по умолчанию работает в режиме `direct` (в обход прокси) напрямую к серверам VK и CDN `vkuseraudio.net` / `mycdn.me`.
  - В настройках предусмотрена независимая проверка задержки и доступности прокси для каждого сервиса.

### ADR-5: Детерминированный алгоритмический сопоставитель (Matching Engine)

- **Контекст:** Названия треков в VK изобилуют опечатками, разной раскладкой, смешением омоглифов (кириллица/латиница), вынесением приглашенных артистов в название `(feat. ...)` и тегами версий.
- **Рассмотренные альтернативы:** AcoustID / Chromaprint (аудио-отпечатки), внешние LLM / платное распознавание.
- **Решение:** Чистый детерминированный алгоритм сопоставления (`src/core/matching.ts`):
  1. Нормализация Unicode (NFD/NFKC) со снятием диакритических знаков (`Beyoncé` -> `Beyonce`).
  2. Фолдинг визуально идентичных букв-омоглифов кириллицы и латиницы (`MOT` <-> `МОТ`, `CMH` <-> `СМН`).
  3. Дедупликация приглашенных авторов: извлечение артистов из названий `feat.` / `with` и их слияние со списком основных исполнителей.
  4. Автосопоставление идентичных версий: если исходный трек и кандидат содержат одинаковую версию/ремикс, совпадение признается валидным.
  5. Мягкая пунктуация для ремиксов и учет имени ремиксера в составе артистов.
  6. Настраиваемый допуск по хронометражу (до 5 секунд по умолчанию) для компенсации пауз тишины MP3 в VK.
  7. Интеллектуальный выбор первичного релиза (сингл vs альбом) с отсечением лайв-записей.
- **Обоснование:** Полная локальность, мгновенная скорость вычисления (1–2 мс на всю библиотеку в 9 000 треков) и предсказуемость результата без затрат сетевого трафика.

### ADR-6: Архитектура фоновых очередей и персистентных задач (Jobs)

- **Контекст:** Поиск по библиотеке из 9 000+ треков занимает значительное время и подвержен разрывам сети и ограничениям частоты запросов.
- **Решение:**
  - Каждое задание (`search`, `transfer`) хранится в таблице `jobs` СУБД SQLite с сохранением текущего курсора.
  - Реализован механизм атомарной паузы и автопродолжения после истечения срока `Retry-After`.
  - При закрытии приложения активное задание переводится в статус `paused` и готово к продолжению после следующего запуска.
  - Троттлинг IPC-уведомлений о прогрессе поиска (интервал 1200 мс) исключает избыточную нагрузку на React-рендер при непрерывном поиске.

### ADR-7: Модульная декомпозиция главного процесса и представлений интерфейса

- **Контекст:** По мере развития функциональности (сетевые прокси, оффскрин-плеер VK, модальные диалоги, 5 форматов экспорта) корневые файлы `src/main/index.ts` и `src/renderer/src/App.tsx` превысили 880 и 1950 строк соответственно, затрудняя сопровождение и увеличивая риск регрессий.
- **Решение:**
  - Декомпозиция `src/main/`: выделение сервисов сетевых прокси (`network.ts`), системных файловых операций и архивации (`files.ts`) и управления сессией браузера VK (`vk-session.ts`). В `index.ts` оставлены только инициализация приложения и маршрутизация строго валидированного IPC.
  - Декомпозиция `src/renderer/src/`: вынос содержимого вкладок в автономные представления (`LibraryView`, `ConnectionsView`, `JobsView`, `ArchiveView`, `SettingsView`), диалогов — в отдельные компоненты (`ImportDialog`, `TransferDialog`). Состояние навигации, фильтров и несохраненных черновиков (`drafts`) сохраняется на уровне `App.tsx` для бесшовного переключения вкладок.
- **Обоснование:** Сокращение объема корневых файлов на 60–62%, устранение связанности модулей, изоляция сайд-эффектов при сохранении 100% обратной совместимости API и интерфейса.

## 4. Модель данных

### Сущность `TrackRow`

- `id`: Уникальный идентификатор записи (UUID v4).
- `position`: Исходный порядковый номер в медиатеке (1-based).
- `source`: Неизменяемые исходные данные (`RawTrack`):
  - `id`: Идентификатор трека в VK (`owner_id_audio_id`).
  - `artist`: Исходный исполнитель.
  - `title`: Исходное название.
  - `duration`: Длительность в секундах (или `null`).
  - `availability`: Статус доступности (`available`, `blocked`, `unknown`).
  - `url`: Прямой URL записи (при наличии).
  - `rawText`: Необработанная текстовая строка или JSON-снимок.
- `working`: Редактируемая рабочая копия (`Working`):
  - `artist`, `title`, `version`: Уточненные метаданные.
  - `excluded`: Флаг исключения из переноса (сохраняется в архиве, но не идет в плейлист).
  - `destination`: Выбранное целевое назначение (`unresolved`, `spotify`, `local`).
  - `spotify`: Подтвержденный кандидат Spotify (`uri`, `title`, `artists`, `duration`, `album`).
  - `local`: Привязанный локальный файл (`path`, `sha256`, `codec`, `bitrate`, `duration`, `size`).
  - `candidates`: Список найденных кандидатов в Spotify.
  - `searchedQuery`: Снимок поискового запроса для валидации кэша.
  - `localPending`: Маркер необходимости подбора локального файла.
  - `reviewDeferred`: Флаг откладывания решения («На потом»).

## 5. Смешанный перенос (Mixed Migration)

Spotify Web API не предоставляет метода для программной загрузки локальных аудиофайлов в облако или добавления их напрямую в плейлист через API без предварительного сканирования десктопным клиентом.

**Схема смешанного переноса в VKSpot:**

1. Каталожные треки добавляются в новый плейлист Spotify через Web API пачками по 100 треков с сохранением исходного порядка.
2. Для редких записей, отсутствующих в каталоге, формируется подготовленная локальная папка аудиофайлов:
   - Файлы копируются без перекодирования звука (чистое побайтовое копирование).
   - Имена файлов содержат префикс позиции в плейлисте (например, `0042 - Artist - Title.mp3`).
3. Пользователь добавляет подготовленную локальную папку в настройки десктопного клиента Spotify («Локальные файлы»).
4. По завершении добавления запускается операция **«Сверить смешанный порядок»** (`reconcileMixed`): алгоритм проверяет соответствие каждого локального URI `spotify:local:...` и каталожного URI плану переноса, гарантируя сохранение 100% исходной последовательности всей коллекции.

## 6. Границы верификации и статус готовности

- **Синтетическая верификация:** 100% модульной логики и Electron E2E-тестов автоматизированы (59 unit-тестов, 41 сценарий Playwright).
- **Пользовательская верификация:** Выгрузка исходной коллекции VK из 8945 записей и фоновый поиск по реальным запросам подтверждены на живых сессиях.
- **Ограничения платформы:** Локальные файлы требуют воспроизведения через десктопное приложение Spotify на тех устройствах, где физически доступны соответствующие аудиофайлы.
