# VKSpot

Локальная библиотека и проверяемый перенос VK Музыки в Spotify.

**Все основные функции работают без дополнительных покупок; любой будущий
платный сервис — только добровольное дополнение с бесплатным вариантом работы.**

## Запуск

Приложение собирается под Windows (x64) с помощью `electron-builder`:

```sh
# Установка зависимостей (требуется Node.js 24 LTS)
npm ci

# Запуск в режиме разработки
npm run dev

# Проверка типов, стилей и тестов
npm run typecheck
npm run lint
npm run format:check
npm test              # 59/59 модульных тестов
npm run test:e2e      # 41/41 сквозной тест Playwright

# Сборка готового установщика
npm run dist:win      # Создаёт release/<версия>/VKSpot Setup <версия>.exe
```

Пользователю готового приложения Node.js, Python, компиляторы и SDK не нужны.
Проект не требует внешнего сервера или аккаунта VKSpot. Название VKSpot не означает
официальную связь с VK или Spotify.

## Возможности

- **Фоновый поиск через веб-плеер Spotify:** включён по умолчанию и не требует Spotify Client ID.
  Приложение автоматически подставляет запросы и считывает кандидатов; при необходимости входа
  или капчи открывает окно Spotify прямо в приложении. Подробнее в [docs/browser-search.md](docs/browser-search.md).
- **Продвинутый алгоритм сопоставления:**
  - Нормализация диакритики (`Beyoncé` ↔ `Beyonce`, `JAŸ-Z` ↔ `JAY-Z`).
  - Распознавание омоглифов кириллицы и латиницы (`MOT` ↔ `МОТ`, `СМН` ↔ `CMH`).
  - Очистка дублирования исполнителей в скобках `(feat. ...)` и `[with ...]`.
  - Автосопоставление идентичных версий (`Remix`, `Mix`, `Edit`, `2026 Version`).
  - Мягкая пунктуация для ремиксов и учет ремиксера среди исполнителей.
  - Настраиваемый допуск по длительности (до 5 секунд) с учетом тишины в начале/конце треков VK.
  - Автоматический выбор основного студийного релиза при наличии дубликатов (сингл vs альбом).
- **Встроенное предпрослушивание аудио:** плееры для воспроизведения треков VK Music и кандидатов Spotify прямо в инспекторе для проверки спорных версий на слух.
- **Интеллектуальная таблица и инспектор:** виртуализированная таблица TanStack для коллекций любого масштаба (9 000+ записей), фильтры по статусам, настраиваемый инспектор (параллельное и последовательное размещение, регулировка ширины).
- **Экран «Начало»:** определяет фактическое состояние библиотеки и предлагает один следующий шаг.
- **Автопродолжение фонового поиска:** сохранение прогресса в SQLite, продолжение после перезапуска и интеллектуальная обработка лимитов `Retry-After` Spotify.
- **Высокая производительность:** многоуровневое in-memory кэширование, сигнатурный пересчёт статусов строк и оптимизация IPC, исключающие лаги и фризы интерфейса.
- **Смешанный перенос:** перенос каталожных совпадений в плейлист Spotify плюс подготовка локальных аудиофайлов для редких треков, отсутствующих на стриминге.
- **Локальное хранение и приватность:** локальная база данных SQLite (WAL-режим), токены авторизации шифруются через системный `safeStorage` ОС, без телеметрии и скрытых отправок данных.
- **Экспорт и архивация:** сохранение полного архива VKSpot, списков TXT/CSV, M3U8 и плана переноса.
- **Системная панель:** мониторинг статусов сессий VK и Spotify в реальном времени, отображение активных задач и прогресса прямо в сайдбаре.

## Начало работы

1. Импортируй список либо открой **Подключения → VK** и самостоятельно войди.
2. Открой именно **Моя музыка**, затем нажми **Выгрузить мой список** в VKSpot.
   Если знаешь точное количество записей, укажи его перед сбором. Приложение
   умеет перейти с главной страницы VK на вкладку личной музыки самостоятельно.
   Если количество неизвестно, оставь поле пустым; указывать число «с запасом» не нужно.
   Пока появляются новые записи, сбор не прерывается по общему таймеру.
3. Сравни количество, первую и последнюю запись с VK. Сохрани полный архив.
4. После сохранения поиск начнётся сам, если оставлена соответствующая галочка.
   Для поиска через страницу Client ID не нужен. Уже приостановленный API-поиск
   переключается кнопкой «Продолжить через страницу Spotify» без сброса прогресса.
   Прогресс и пауза видны в таблице, остальные параметры — в «Параметрах поиска».
5. Нажми «Выделить совпадения», проверь выборку и «Подтвердить выбранные».
   Фильтры результата, назначения и текстовый поиск работают вместе.
   Спорную запись открой стрелкой для подробного сравнения.
   После решения открывается следующая запись. Подробные критерии и ограничения —
   в [описании разбора](docs/matching-workflow.md).
6. Привяжи файлы отсутствующих в каталоге записей. Ненужные пометь «исключить».
7. Проверь план и запусти перенос. Неподготовленные записи не пропускаются скрыто.
8. Добавь локальные записи через приложение Spotify; затем запусти **Сверить
   смешанный порядок** в задании. Для автоматической связи нужны корректные
   теги исполнителя, названия и длительность. При несоответствии проверка
   остановится до перестановки.

## Подключение Spotify API для переноса

Поиск через страницу Spotify не требует этого подключения. Для создания плейлиста
открой **Подключения → Spotify API — подключение для переноса**.

Создай личное приложение в [Spotify Developer](https://developer.spotify.com/dashboard).
Добавь точный Redirect URI:

```text
http://127.0.0.1:43823/callback
```

Сохрани Client ID кнопкой **Сохранить настройки Spotify** и нажми **Войти в Spotify**.
Client Secret не нужен.
Вход в API выполняется в системном браузере. Встроенная страница Spotify имеет
отдельную локальную сессию; пароль при необходимости вводится на сайте Spotify.
Spotify требует Premium у владельца Development Mode приложения и ограничивает
доступ разрешёнными пользователями. Client ID не платный ключ. Бесплатный путь
переноса без этого API-подключения пока не подтверждён; поиск через страницу
и локальные функции от него не зависят.

Если Spotify сообщает `Spotify is unavailable in this country`, открой поле
**Прокси Spotify** и укажи HTTP или SOCKS5 адрес своего VPN, например
`http://127.0.0.1:2080`, затем сохрани настройки. Адрес и порт должны соответствовать
твоему VPN-клиенту. Пустое поле использует системные настройки сети.
Прокси применяется только к запросам Spotify, включая обмен и обновление токена;
окно VK и локальный адрес возврата не меняются.

Полученный токен сам по себе не включает статус «Подключён»: приложение сначала
проверяет доступ к профилю через API. После смены прокси сохранённая сессия
проверяется повторно; новый вход нужен, только если она уже недействительна.
Прокси с логином и паролем в адресе этой версией не поддерживаются.

## Форматы импорта

JSON: массив объектов или `{ "tracks": [...] }`.

```json
[
  {
    "id": "123_456",
    "artist": "Исполнитель",
    "title": "Название (Remix)",
    "duration": 185,
    "availability": "blocked"
  },
  { "id": "123_456", "artist": "Исполнитель", "title": "Название (Remix)", "duration": 185 }
]
```

Повтор здесь намеренный и сохраняется двумя отдельными записями.
CSV: заголовки `artist,title,duration` или `Исполнитель,Название,Длительность`;
поддержаны запятая, точка с запятой и табуляция, кавычки и многострочные поля.
TXT: одна запись на строку, `Исполнитель - Название` либо только название.
Для точного восстановления правок используй **полный архив VKSpot**, не CSV.
Пустые строки TXT пропускаются; пробелы внутри исходных полей не очищаются.

## Реальные ограничения первой версии

- Владелец получил и сохранил архив из 8945 записей VK и сверил крайние записи.
  Счётчик VK Музыки показывает 8927: причина разницы в 18 записей не установлена;
  независимое подтверждение общего количества остаётся открытым.
- 15.10.2026 проверены профиль Spotify и один поиск через локальный VPN-прокси
  с сессией владельца в изолированном профиле приложения. Доступ без прокси
  возвращал региональный отказ. Создание плейлиста и перенос ещё не проверены
  на настоящем аккаунте; диагностическая проверка ничего в Spotify не меняла.
- 18.10.2026 в отдельном профиле без Client ID выполнены три read-only запроса
  через встроенную страницу Spotify: два обычных вернули кандидатов и метаданные,
  а искусственный запрос — неточные варианты для ручного разбора. Использовался
  локальный VPN-прокси. Это подтверждает поиск на проверенных запросах, но не
  проверяет очередь из 8000+ записей, вход в аккаунт внутри встроенной страницы
  или создание плейлиста. Подробности: [живой прогон](docs/browser-search.md).
- VK DOM-адаптер зависит от разметки и виртуализации страницы. Без ожидаемого
  количества конец загруженной страницы не подтверждает полноту библиотеки.
  Заблокированные файлы не восстанавливаются автоматически. Подробности и
  проверки описаны в [выгрузке VK](docs/vk-extraction.md).
- Загрузчик аудио из VK пока не реализован. Привязка и подготовка уже имеющихся
  файлов работают. Поиск доступного оригинального источника требует отдельного
  проверенного адаптера, а не обещания вернуть исходник.
- Spotify API не добавляет локальные файлы. Windows-помощник пока открывает
  Spotify и проверяет доступные элементы UI Automation; массовое добавление
  через него не заявляется как работающее.
- Смешанный порядок сверяется по уже добавленным URI. Это не подтверждает
  воспроизводимость файла на другом устройстве и не заменяет проверку версии на слух.
- Правила обработки неясных названий специально оставлены для следующего
  обсуждения. Автоматического переименования и угадывания версий нет.
- Подготовленные имена файлов отражают позиции, но не меняют встроенные теги.
- Локальные копии можно подготовить до сопоставления остальных записей; в
  сопровождающем плане неразрешённые и исключённые позиции остаются видимыми.
- Полный архив включает пути и метаданные, но не сами аудиофайлы и не токены.
- Текущее приложение не скачивает FFmpeg, .NET SDK или платные сервисы при запуске.
- Установщик этой локальной сборки не подписан сертификатом издателя.

## Хранение и приватность

Данные лежат в стандартной папке приложения, показанной в **Настройках**.
`collection.db` — SQLite с WAL, транзакциями и запретом изменения исходных полей.
`spotify.enc` — токены, зашифрованные системным хранилищем Electron safeStorage.
Если защищённое хранилище недоступно, токены не записываются открытым текстом.
VK хранится в отдельной браузерной сессии; кнопка выхода очищает её.
Телеметрия и отправка коллекций на сервер VKSpot отсутствуют.
Не публикуй свои архивы и папку данных вместе с исходниками.

## Выбор зависимостей

Предложенный стек в docs/project-brief.md — план, а не список обязательных пакетов.
В этой реализации SQLite использует встроенный `node:sqlite` из поставляемого
Electron/Node вместо ABI-зависимого better-sqlite3. Переход проверяется тестами.
XState, Drizzle, платные сервисы, распознавание AcoustID и C#-помощник не
подключены спекулятивно: сначала нужно подтвердить сценарии и контракты.
Задачи сейчас имеют явно описанные состояния и локальный журнал SQLite.
Обновления пока устанавливаются пользователем; автоматическое обновление
требует отдельного подписанного канала выпусков.

## Проверки и вклад

`npm test` проверяет архивирование, Unicode, повторы, смешанный план, отмену,
транзакции, потерю ответа Spotify и защиту от повторного создания плейлиста.
`npm run test:e2e` запускает настоящий Electron с временной изолированной базой,
проверяет правки, исключения, отмену и перезапуск.
Проверены также 9000 отдельных вхождений, чтение локального аудио и копирование
без изменения байтов. ESLint и Prettier проверяют качество и читаемость исходников.
GitHub Actions повторяет проверки на Windows. Для изменения адаптеров нужны
обезличенные фикстуры и тесты, без токенов, паролей и личных музыкальных архивов.
